= Column Types
:data-types: https://docs.oracle.com/en/database/oracle/oracle-database/26/sqlrf/Data-Types.html

Every column type the tables of `CO`, `HR` and `SH` declare, grouped by the sections of
link:{data-types}[Data Types]
in the Oracle Database 26 SQL Language Reference. Each type is listed as the DDL declares it --
`db-sample-schemas/customer_orders/co_create.sql`, `human_resources/hr_create.sql` and
`sales_history/sh_create.sql` -- and each column as `SCHEMA.TABLE.COLUMN`; 214 columns in all (43 in
`CO`, 35 in `HR`, 136 in `SH`). The views declare no column of their own; see <<views>>.

The Java type is the preferred type of an attribute mapping the column, the one the `Mapped*`
classes use; `java.time` for the datetime types, and the wrapper types, never a primitive, since
any column may be `NULL` on a row the database returns. An attribute may still take another type
where the application decides it -- `CO.ORDERS.ORDER_STATUS` and `CO.SHIPMENTS.SHIPMENT_STATUS` are
enums.

Only the sections below are used. No column is `NCHAR`, `NVARCHAR2`, `FLOAT`, `BINARY_FLOAT`,
`BINARY_DOUBLE`, `LONG`, `RAW`, `LONG RAW`, `TIMESTAMP WITH (LOCAL) TIME ZONE`, an `INTERVAL`,
`CLOB`, `NCLOB`, `BFILE`, `JSON`, `BOOLEAN`, `VECTOR`, `ROWID` / `UROWID`, a user-defined type or an
Oracle-supplied type (`ANYDATA`, `XMLType`, `SDO_GEOMETRY`, ...).

=== Numeric Data Types

See link:{data-types}#GUID-9401BC04-81C4-4CD5-99E7-C5E25C83F608[Numeric Data Types].

Only `NUMBER`. With no precision it holds any value up to 38 significant digits; `NUMBER(p)` is
`NUMBER(p,0)`, an integer of at most `p` digits.

`NUMBER(p)` is an `Integer` up to 9 digits and a `Long` up to 18, the most each holds; a scale
makes it a `BigDecimal`. A `NUMBER` with no precision is a `Long`: every such column here holds an
integer, an identifier, a count or a limit, though the type itself also admits a fraction, which a
`BigDecimal` would keep.

A column which holds another table's key takes that key's type instead, whatever it declares, so
that the two compare: `SH.SALES.CHANNEL_ID`, a `NUMBER(1)`, is a `Long` as
`SH.CHANNELS.CHANNEL_ID` is, and `SH.COSTS.PROD_ID` and `SH.COSTS.PROMO_ID`, plain `NUMBER`s, are `Integer`s as
`SH.PRODUCTS.PROD_ID` and `SH.PROMOTIONS.PROMO_ID`, both `NUMBER(6)`, are.

[[views]]
== Views

A view's columns take the types of the expressions that select them, so the views add no type
outside the sections above:

* `CO.PRODUCT_REVIEWS` declares its own two in `JSON_TABLE`: `RATING INTEGER` and
  `REVIEW VARCHAR2(4000)`. `AVG_RATING` is a `ROUND` of an `AVG`, a `NUMBER`.
* The aggregates (`SUM`, `COUNT`) of `CO.CUSTOMER_ORDER_PRODUCTS`, `CO.PRODUCT_ORDERS`,
  `CO.STORE_ORDERS`, `SH.CAL_MONTH_SALES_MV` and `SH.FWEEK_PSCAT_SALES_MV`, and
  `SH.PROFITS.TOTAL_COST` (a product of two `NUMBER` columns), are `NUMBER` with no precision.
* `CO.CUSTOMER_ORDER_PRODUCTS.ITEMS` (a `LISTAGG`) and `CO.STORE_ORDERS.ADDRESS` (a `COALESCE` of
  two `VARCHAR2` columns) are `VARCHAR2`. `CO.STORE_ORDERS.TOTAL`, a `CASE` of text literals, is a
  character type, `CHAR` or `VARCHAR2`; the data dictionary says which.
* Every other view column is a table column, and has its type.
