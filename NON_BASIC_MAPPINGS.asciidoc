= Non-Basic Mappings

The mappings of `CO`, `HR` and `SH` which are more than a basic attribute of a scalar column,
leaving out associations and the composite keys (`OrderItemId`, `ProductOrderId`, `SalesId`, ...).
For the column types themselves, see link:COLUMN_TYPES.asciidoc[Column Types].

No column is XML, `JSON`, spatial or of any other Oracle-specific type: no `XMLType`, `JSON`,
`SDO_GEOMETRY`, `ROWID` / `UROWID`, `INTERVAL`, `BFILE`, `VECTOR` or `BOOLEAN`, and so no document
typed by an XML schema (see <<xml-schemas>>). What is left is three
`BLOB` columns, one of which holds JSON, in `CO`; a few embeddables; and enums and converters. `HR`
has none.

[[xml-schemas]]
== XML schemas

The sibling `sqlserver-samples-persistence` reads `XML` columns of AdventureWorks typed by XML schemas
which Microsoft publishes under `http://schemas.microsoft.com/sqlserver/`, bound to Java by
`io.github.jinahya:sqlserver-xml-schema-binding` -- `ContactInfo`, `IndividualSurvey`, `Resume`,
`StoreSurvey`, ... for the sample data, and `showplan`, `eventdata`, ... for the product.

Nothing of the kind applies here: `CO`, `HR` and `SH` declare no `XMLType` column, so no document of
these schemas is typed by an XML schema. Oracle does supply XML schemas, but of two other kinds:

* Oracle XML DB's own, listed in
  link:https://docs.oracle.com/en/database/oracle/oracle-database/26/adxdb/oracle-supplied-XML-schemas-and-examples.html[Oracle-Supplied XML Schemas and Examples]
  and registered in the database's repository under `/sys/schemas/PUBLIC/xmlns.oracle.com/xdb/`,
  not published on a web site as Microsoft's are:
+
[cols="2,4,4",options="header"]
|===
| Schema | `targetNamespace` | For

| `XDBResource.xsd` | `http://xmlns.oracle.com/xdb/XDBResource.xsd` | a resource of Oracle XML DB Repository
| `XDBResConfig.xsd` | `http://xmlns.oracle.com/xdb/XDBResConfig.xsd` | the configuration of repository resources
| `acl.xsd` | `http://xmlns.oracle.com/xdb/acl.xsd` | an access control list
| `xdbconfig.xsd` | `http://xmlns.oracle.com/xdb/xdbconfig.xsd` | the configuration of Oracle XML DB
| `xdiff.xsd` | `http://xmlns.oracle.com/xdb/xdiff.xsd` | the `diffXML` of `DBMS_XMLSCHEMA.inPlaceEvolve`

|===
+
They describe the database's own repository, not application data, so no column of a sample schema
holds them.
* The sample data's own: `OE.PURCHASEORDER` holds `XMLType` documents conforming to
  `purchaseOrder.xsd`, the purchase-order schema of the XML DB examples, and
  `OE.WAREHOUSES.WAREHOUSE_SPEC` is an `XMLType` with no XML schema. `OE` (Order Entry) is archived
  since the Oracle Database 23 release of `db-sample-schemas`, with `PM` (Product Media), and is not
  mapped by this project.

An Oracle counterpart of `sqlserver-xml-schema-binding` would therefore bind the XML DB schemas above,
and, for the sample data, `purchaseOrder.xsd` -- only were `OE` mapped.

[[json]]
== JSON

`CO.PRODUCTS.PRODUCT_DETAILS` holds JSON, but as a `BLOB` checked by `products_json_c`
(`CHECK ( product_details is json )`), not as a `JSON` column. The mapping keeps the bytes, and the
document is read outside of it:

* `ProductDetails` (main, `co.mapped`) is a plain class for the document, with a nested `Review` for
  each element of `$.reviews`; it is neither an entity nor an embeddable.
* `MappedProduct.getProductDetailsAsMapped(Function)` and `setProductDetailsFromMapped(...)` take the
  function which converts between the bytes and the document; the module chooses no JSON library.
  The tests use Jackson (`ProductDetails_TestUtils`).
* The view `CO.PRODUCT_REVIEWS` reads the same document with `JSON_TABLE` on the database side, and
  declares `RATING INTEGER` and `REVIEW VARCHAR2(4000)`. Its mapping, `ProductReview` over
  `MappedProductReview`, sees plain columns; being keyless, it is a class, not an entity.

== Embeddables

None of these is embedded yet: each table maps the same columns as plain attributes.

[cols="2,3,5",options="header"]
|===
| Class | Columns | Note

| `ProductImage` (`CO`)
| `PRODUCTS.PRODUCT_IMAGE`, `IMAGE_MIME_TYPE`, `IMAGE_FILENAME`, `IMAGE_CHARSET`,
  `IMAGE_LAST_UPDATED`
| Extends `MappedBinary` (`@Lob byte[] bytes`, `mimeType`, `filename`, `charset`, `lastUpdated`),
  and names the columns with `@AttributeOverride`s. `MappedProduct` maps them itself.

| `StoreLogo` (`CO`)
| `STORES.LOGO`, `LOGO_MIME_TYPE`, `LOGO_FILENAME`, `LOGO_CHARSET`, `LOGO_LAST_UPDATED`
| The same, over `MappedBinary`. `MappedStore` maps them itself.

| `CountrySection` (`SH`)
| `COUNTRIES.COUNTRY_SUBREGION` / `COUNTRY_SUBREGION_ID`, `COUNTRY_REGION` / `COUNTRY_REGION_ID`,
  `COUNTRY_TOTAL` / `COUNTRY_TOTAL_ID`
| Declares no column names; an embedding entity would name both. `MappedCountry` maps each pair
  itself.

|===

== Enums and converters

[cols="2,2,3,3",options="header"]
|===
| Column | Java type | Mapping | Applied

| `CO.ORDERS.ORDER_STATUS`
| `MappedOrder.OrderStatus`
| `@Enumerated(EnumType.STRING)`
| yes

| `CO.SHIPMENTS.SHIPMENT_STATUS`
| `MappedShipment.ShipmentStatus`
| `@Convert(converter = ShipmentStatusConverter.class)`, a nested `@Converter(autoApply = false)`
| yes

| `SH.TIMES.DAY_NAME`
| `DayOfWeek`
| `TimeDayNameAttributeConverter`
| no, an exercise (issue #6)

| `SH.TIMES.CALENDAR_MONTH_NAME`, `FISCAL_MONTH_NAME`
| `Month`
| `TimeMonthNameAttributeConverter`
| no, an exercise (issue #7)

| `SH.TIMES.CALENDAR_MONTH_DESC`, `FISCAL_MONTH_DESC`
| `YearMonth`
| `TimeMonthDescAttributeConverter`
| no, an exercise (issue #8)

|===

The three `SH` converters are `autoApply = false`, and listed in each unit of `persistence.xml`, but
no attribute names them: `MappedTime` keeps the columns as `String`s, and `TimeUtils` derives the
`DayOfWeek`, `Month` or `YearMonth` on demand. `SH.CAL_MONTH_SALES_MV.CALENDAR_MONTH_DESC` holds the
same text as `TIMES.CALENDAR_MONTH_DESC`, but it is that view's `@Id`, which the specification
excludes from attribute conversion.
